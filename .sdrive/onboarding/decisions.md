## Product overview — approved via interview

`README.md` is unmodified `create-next-app` boilerplate (scan quality:
`template`), so the scan correctly refused to treat it as the vision. Onboarding
kept a code-derived draft, then interviewed the owner. The approved overview was
written to `.sdrive/product/overview.md` on 2026-10-18 with `Status: Approved`:

- **Organizer-first:** the organizer workflow (publish → fill → check in) is the
  product; attendee discovery is a distribution channel.
- **Global:** Nigeria is not the only target; the Nigeria-first implementation
  (`NG` pickers, naira, seed cities) is recorded as an implementation gap.
- **Segments:** organizers are primary, attendees secondary, admins internal.
  Communities/schools and professional organizers/agencies are growth segments.
- **Non-goals:** online payments, native apps, sponsor/seating/streaming, multi-tier
  ticketing, and complex team roles in v1.

The previous derived draft is preserved at the bottom of the file under
`## Previous draft (derived)`, with no competing headings so the dashboard parser
keeps reading the approved sections.

## Retroactive specs — four features

The code was documented as four retroactive features:

| Feature | Scope |
| --- | --- |
| `event-discovery-and-registration` | Explore, category/location, event page, search, registration, QR tickets, attendee onboarding. |
| `event-management-and-check-in` | Create event, free/Pro limits, cover upload, My Events, dashboard, QR check-in, search, CSV. |
| `admin-console-and-governance` | Admin access, totals, users, events, registrations, invites, audit, analytics, preferences. |
| `ai-event-creation` | Cerebras-backed prompt-to-draft flow and its failure modes. |

Each has `spec.md`, `plan.md`, `tasks.md` under
`.sdrive/specs/ongoing/<feature>/v1/` and `spec.json`, `plan.json`, `tasks.json`,
`traceability.json` under `.sdrive/governance/<feature>/v1/`.

The specs are kept under `ongoing/` and the version `phase` is `completed`,
exactly as the onboarding command specifies. That combination is unusual: the
folder says "active product surface" while the phase says "record closed". It is
used here to mean "shipped behaviour, documented after the fact". If these should
behave as archived records for `/sdrive:review` and `/sdrive:archive`, move each
feature folder to `.sdrive/specs/completed/`; no governance path changes.

**Retroactive marking.** The specs are marked three ways: `retroactive: true` in
the `spec.md` frontmatter, a retroactive statement in each `overview.assumptions`,
and membership in `workflow-state.json → onboarding.retroactiveFeatures`. The
marker is **not** written as a top-level key in `spec.json` because
`spec.schema.json` sets `additionalProperties: false`; adding it would make the
artifact invalid. This is a framework inconsistency, described below.

## Framework issues found

Items 1–3 are recorded rather than patched, because fixing them would modify
SpecDrive itself. Item 4 was a project configuration problem and is fixed.

1. `onboard.js` writes `onboarding.projectBrief`, but
   `workflow-state.schema.json` sets `additionalProperties: false`. The key was
   removed so validation passes; the brief still lives in
   `.sdrive/product/overview.md`.
2. `migrate-openspec.js` / `migrate-speckit.js` write `retroactive` and
   `migratedFrom` into `spec.json`, which `spec.schema.json` rejects. No
   migration ran here, so nothing was affected.
3. `validate-governance.js` requires Ajv 8, but this project resolves Ajv 6 from
   the root `node_modules`. Validation was run through
   `.sdrive/onboarding/validate.js`, which redirects only the `ajv` specifier to
   the Ajv 8 copy nested under `ajv-formats`. The framework script was not edited.
4. **Fixed.** `eslint.config.mjs` did not ignore `.sdrive/**` or
   `convex/_generated/**`, so `npm run lint` reported CommonJS `require` errors
   from framework scripts and generated files. Both globs were added to
   `globalIgnores`, and the carousel's initial Embla select was moved into a
   `requestAnimationFrame` callback so it no longer sets state synchronously
   inside an effect.

## Product gaps documented in the retroactive specs

- Admin registration cancellation calls the attendee mutation and therefore
  cannot cancel another user's ticket; no `registration.cancelled` audit entry is
  written (`admin-console-and-governance`, RISK-001).
- `getAllUsers` searches only the first 100 rows (RISK-002).
- `freeEventsCreated` is incremented for every created event but reclaimed only
  for free-ticket deletions (`event-management-and-check-in`, RISK-001).
- `/api/generate-event` is unauthenticated and unrate-limited, the model output is
  not schema-validated, and the client ignores `response.ok`
  (`ai-event-creation`, RISK-001 to RISK-003).
